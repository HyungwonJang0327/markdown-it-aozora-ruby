# 아키텍처 — 토큰 변환 전략

- **결정**: markdown-it **core ruler**에서 inline 파싱 완료 후 text 토큰을 전용 토큰 시퀀스(`ruby_open` / `ruby_rt_open` / `ruby_rt_close` / `ruby_close` + text)로 분해하고, `md.renderer.rules`에 전용 렌더러를 등록한다. 표기법 매칭 로직은 `notations.ts`의 매처(정규식 + 캡처 해석 함수)로 분리해 향후 다른 표기법 추가 시 매처 배열에만 추가하면 되게 한다.
- **이유**: 아오조라 표기는 베이스 한자가 매치 지점(`《`) *앞*에 오므로 "현재 위치에서 시작하는 매치"만 다루는 inline ruler와 구조적으로 안 맞는다. core 단계에서 text 토큰만 변환하면 코드 스팬/펜스 안의 `《》`는 자동으로 보호된다. 전용 토큰을 쓰면 raw HTML(`html_inline`)을 쓰지 않아 새니타이저·AST 도구와 호환된다.
- **기각된 대안**:
  - inline ruler + `state.pending` 되감기 — 다른 inline 플러그인과의 실행 순서에 따라 깨지는 해키한 방식. 베이스가 이미 다른 토큰으로 분리된 경우(`**漢字**《…》`) 처리 불가.
  - `html_inline` 토큰 유지(Justdown 현행) — "사용자가 쓴 raw HTML" 시맨틱이라 새니타이저가 제거할 수 있고, 독립 패키지 품질로 부족.
- **한자 매칭**: `\p{Script=Han}` + `u` 플래그. 기존 Justdown 정규식(`[㐀-䶿一-鿿々〆ヶ豈-﫿]`)은 BMP만 커버해 CJK 확장 B 이후(예: 𠮟 U+20B9F)를 놓친다. `々〆ヶ` 등 Han 스크립트 외 문자는 별도 클래스로 유지 여부를 구현 시 테스트로 검증한다.
